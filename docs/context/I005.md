# Cost Lists

A cost list holds what you pay per unit of an item or service. Purchase lines take
their **Purchase Amount** from it, and work orders take their **Cost Per Unit**.

## How a cost is chosen

1. **The line must match exactly:** same item, and costed per the same unit.
2. **The list must be in force** on the date: the order date for a purchase line, or
   the actual finish (else actual start) for a work order.
3. **Every other condition must be blank or match:** party (the seller, or the
   work order's worker), SKU, ports (a port group counts for its ports), container
   type and class, and the list's work zone.
4. **The most specific match wins.** Each matching condition counts one point. A
   list linked to the party's **market** counts ten. Markets don't exclude anyone.
5. **Ties go to the lower Priority number.**
6. **No match:** the item's **Default Cost** is used if the line is per the item's
   purchased unit. Otherwise the amount is left as it is.

A typed amount is kept when the lookup comes back with the same list row. Opening a
saved line or work order never looks up a cost.

## Work orders

- A work order looks up its cost when its item, unit, worker, ports, work zone,
  container type or actual dates change.
- Changing the work item type always takes the new item's cost.
- A work order made from a template with a locked rate never looks up its cost.
- A work zone on the list limits it to work orders in that zone. A list with a work
  zone is never used for purchase lines.

## Things to know

- **Priority** is 1 to 100. New lists start at 5.
- **Expires stops lookups at the start of that day.** The grid still shows the list
  as in force on its Expires day. To use a list through a day, expire it the next
  day.
- **Clone** copies the list, its markets and its lines to a new list.
- The grid starts on today's date. Clear the date to see every list.

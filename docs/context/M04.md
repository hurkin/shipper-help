# Process Inventory

Process Inventory records processing against a work order: what was used and what
was made. For example, raw bales go in and compressed sleeves come out.

## Using it

1. Choose the work order.
2. Scan or pick what was used: tags (each goes whole) or SKUs (choose how much raw
   and processed to take from each location).
3. Click **Process** and fill in what was made:
   - **Processed Quantity:** how many processed units were produced.
   - **To Location:** where they are. Blank uses the first line's location.
   - **Processed SKU:** blank uses the first line's SKU. Shipper usually keeps the
     same SKU from raw to processed, so it stays traceable.
   - **Complete the work order** to set its actual finish now.

## Things to know

- **Everything or nothing.** If any line fails, nothing is recorded.
- The processed output is written one second after the deductions, so the balance
  never shows both.
- Without a processed quantity, Process just deducts, like Ship.
- If you don't complete the work order, it is started (if it hadn't been).

## In the mobile app

- Process moves product out of raw inventory and into processed inventory before
  the container arrives. It is shipped later with [Ship](M05.md).
- **Enter the processed quantity and choose whether to finish the work order
  before you press ADD.** They can't be added afterwards.
- A SKU tag also needs the **FROM** location and the raw quantity.
- The extra fields only show after a tag is scanned. Without a physical tag, enter
  0 as the barcode, tap **Scan**, then go back.
- Press **DONE** to save. Nothing is saved until you do.

# Queue Setup

This is where queues are defined: what they hold, who uses them and where items go
next.

## Things to know

- **Code** is a short unique code (up to 10 characters, in capitals) used by the
  system. It can't be changed once the queue is saved.
- **Display Folder** groups queues in the queue lists. **Sort Order** orders them.
- **Max Hours In Queue** is how long an item can wait before it shows as overdue.
- **What a queue holds:** tick Agreement, Bill or Booking. An agreement or bill
  queue can be limited to one agreement or bill type. With no type, it takes every
  type.
- **Starting points:** tick **New Agreements**, **New Bills** or **New Bookings**
  to have every new record of that kind (and type) start in this queue. Records
  copied with Clone don't.
- **Next Queue** is where **Next Queue** sends items. Leave it empty for the last
  queue in a path.
- **Roles that see and work it**: only these roles see the queue and
  take items out. Empty means everyone.
- **Roles that may add**: only these roles can put items in, including
  moving items in from the previous queue. Empty means everyone.
- Role names are the roles set up in HAAL, the user management tool. Matching is
  by part of a name: a role called *Sales* also matches a list naming *Sales
  Manager*. Give roles distinct names.
- A queue used for shipline changes is set up by support.
- Queues are deactivated, not deleted.

## Diagram

Switch from **Grid** to **Diagram** to see your workflow: each queue is a box, with
an arrow to its next queue and its scheduled jobs listed inside. Queues read left
to right along their path, and a queue that loops back has an arrow back. Click a
box to open the queue. The diagram follows the Active / Inactive filter.

## Seeing every queue

At its highest level, this feature lets someone see every queue on the Queues pages,
including ones outside their roles. They can look but not work them.

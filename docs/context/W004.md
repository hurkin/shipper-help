# Work Order Scheduler

The scheduler orders planned work for the whole company, a work zone or a work
center across a range of days. The order it saves is used by every work order grid
and the schedule reports.

## Using it

- The list has an **Overdue** section (not started, planned before the first day),
  one section per day, and **Unscheduled** (no planned date). You can move work out
  of Overdue but not into it.
- Drag rows, or use the buttons and keys: up and down, top or bottom of day,
  previous or next day, **Move to date**, and **Unschedule**. Shift-click and
  Ctrl-click select several rows to move as a block.
- **Spread** places the selection a set number per day from a start date,
  optionally skipping weekends. Use it after cloning.
- **Clone** makes up to 50 copies of a work order. Copies appear as *New* rows and
  are created when you save.
- Nothing is written until **Save**. **Undo**, **Redo** and **Discard** work until
  then.

## Bulk Edit

Bulk Edit sets the same values on several work orders at once, such as a new
worker, work center or cost for a week's hauls.

1. Save or discard any schedule changes first. Bulk Edit is unavailable while the
   schedule has unsaved changes.
2. Select the work orders: click one, then Ctrl-click or Shift-click for more.
3. Click **Edit N Selected**. The dialog is laid out like a work order's General
   tab.
4. Fill in only the values to change, then click **Update N Work Orders**.
5. Each work order's result is listed: Saved, Nothing to set, Skipped or Failed,
   with any value it didn't take and why. Click **Close**. The schedule reloads,
   and the work orders that were skipped or failed stay selected so you can try
   them again.

You can set the movement type, work item type, worker and worker contact, work
zone and work center, quantity and unit type, from and to ports, cost per unit,
priority, references 1 and 2, memo, shipment and asset. Planned dates are set on
the schedule itself.

- **Only the values you fill in are changed.** Blank values are left alone, so Bulk
  Edit can't clear a value.
- Each work order is saved on its own, so one failure doesn't stop the rest.
- It works as editing each work order does: a new worker clears the worker
  contact, a new work zone clears a work center outside it, a new work item type
  takes its unit, and the cost is looked up again from your cost list when the
  values it depends on change.
- Some values aren't taken, and the result says so: a work item type or cost
  locked by a work order template, a quantity in a weighed unit (the scale sets
  it), and a shipment on a work order that is on a cargo (it keeps the cargo's).
- Posted work orders are skipped.

## Rules

- **Started work orders are locked.** They show on their day but can't be moved or
  re-timed. Others are ordered around them.
- **Times never run backwards within a day.** A moved row keeps its time if it fits
  between its neighbours. Otherwise it takes the time of the row above (or below,
  at the top of a day). Rows you didn't move keep their times.
- Editing a time moves the row to its place in the day.
- A row moved from Unscheduled takes the time of a neighbour, or midnight.
- Moving a row moves its planned finish by the same amount.
- **Reports group by the UTC day.** A work order planned late in the evening can
  fall on the next day in reports. The scheduler marks these rows and says how
  early to plan to keep them on the day.
- If someone changed a work order since you loaded the list, Save stops and nothing
  is saved. Reload and try again.

## Who can do what

Opening the scheduler needs the Work Order Scheduler feature (owners too). Reading
work orders lets you view it. Moving, cloning and saving need delete rights on work
orders. Bulk Edit needs write rights on work orders.

# Queues

A queue is a team's to-do list. Each stage (Inbound, Processing, Outbound,
Documentation) lists its queues, with how many items are waiting and how many are
overdue.

## Working a queue

- **Next Queue** moves the selected items to the queue's next queue. If there is no
  next queue, it takes them out.
- **Set Completed** stamps the chosen date as Completed on the selected agreements,
  bills or bookings. Posted items are skipped. It isn't offered on queues that mix
  kinds of records.
- Click an item to open it.
- An item is **overdue** when it has waited longer than the queue's maximum hours.
  The wait counts from when the item was first added, and **Next Queue** keeps that
  time.

## Who sees what

- You see a queue only if one of your roles is in its **Roles that see and work it**
  (or that list is empty).
- To move items on, you also need to be allowed to add to the next queue (its
  **Roles that may add**).
- Working queues needs Write on this feature. With Read, you can look but not move.
- Someone with the Queues setup feature at its highest level sees every queue, but
  can only work the ones their roles allow.

## Things to know

- Use **Next Queue**, not taking out and re-adding. It keeps the item's history.
- A queue isn't a status. Completed work shouldn't stay in a queue.
- *Add to Queue* scheduled jobs run when an item is added to a queue, not when it
  arrives through **Next Queue**.
